= RA-2025-11-20: Security vulnerability fixed in RNP 0.18.1

== Metadata

ID:: RA-2025-11-20

This advisory notice covers the following:

* <<CVE-2025-13470>>


[[CVE-2025-13470]]
== CVE-2025-13470

Name:: Use of Insufficiently Random Values in Session Key Generation for PKESK
Link:: https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2025-13470[CVE-2025-13470]
Problem:: https://cwe.mitre.org/data/definitions/CWE-330[CWE-330^] Use of Insufficiently Random Values
CVSS Score:: 7.5 (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N)
Severity:: High
Affected vendors:: Ribose
Affected products:: https://www.rnpgp.org[RNP], version 0.18.0 ONLY

=== Summary

RNP version 0.18.0 contains a vulnerability in session key generation for
PKESK (Public Key Encrypted Session Key) packets. Session keys are generated
without cryptographically random values.

**Users of RNP 0.18.0 should upgrade to version 0.18.1 or use version 0.17.1.**


=== Vulnerability details

During refactoring, the session key initialization for SKESK (passphrase-based
encryption) was correctly updated. However, the corresponding initialization for
PKESK (public key encryption) was not implemented, resulting in vulnerable
session keys.

The vulnerability affects only public key encryption (PKESK packets).
Passphrase-based encryption (SKESK packets) is not affected.


=== Technical impact

Messages encrypted with RNP 0.18.0 using public key encryption use vulnerable
session key values. This is a confidentiality issue for PKESK-encrypted data.

**Encryption types affected:**

* Public key encryption (PKESK) - **AFFECTED**
* Passphrase-based encryption (SKESK) - **NOT AFFECTED**


=== Security impact

Messages encrypted with RNP 0.18.0 using public key encryption use vulnerable
session key values. This is a confidentiality issue for PKESK-encrypted data.


=== Affected versions

* **AFFECTED:** RNP version 0.18.0 ONLY
* **NOT AFFECTED:** RNP version 0.17.1 and all earlier versions
* **NOT AFFECTED:** https://www.thunderbird.net[Thunderbird] (all versions) - uses bundled RNP 0.17.1
* **Fixed in:** RNP version 0.18.1 and later

==== Not affected

* **RNP 0.17.1 and earlier versions** - This vulnerability was introduced in
  version 0.18.0 only. Users of 0.17.1 are not affected.

* **Thunderbird users** - **Thunderbird is NOT AFFECTED.** Thunderbird uses
  bundled RNP version 0.17.1 and does not utilize system-installed RNP
  libraries. Since Thunderbird uses version 0.17.1, which is not affected by
  this vulnerability, all Thunderbird users are unaffected regardless of the
  system RNP version.

* **Users who have already upgraded to RNP 0.18.1 or later**


=== Solution

==== Recommended action

**Option 1 (Recommended):** Upgrade to RNP 0.18.1 when available.

**Option 2 (Interim):** Use RNP 0.17.1 until 0.18.1 is available.

**Via package managers:**

Check your distribution's package repositories for updated packages. If
RNP 0.18.1 is not yet available, version 0.17.1 may be used as an interim
solution.

==== Data handling recommendations

Users who encrypted sensitive data using RNP 0.18.0 should consider
re-encrypting that data with RNP 0.18.1 or 0.17.1 based on their security
requirements and threat model.

=== Frequently asked questions

==== Is Thunderbird affected?

No. Thunderbird uses bundled RNP version 0.17.1, which is not affected by
this vulnerability. Thunderbird does not use system-installed RNP libraries.

==== Is RNP 0.17.1 affected?

No. Only version 0.18.0 is affected. RNP 0.17.1 and all earlier versions
are not affected.

==== Can I use RNP 0.17.1?

Yes. Version 0.17.1 is a suitable interim solution until 0.18.1 is available.

==== What about data I encrypted with 0.18.0?

Users should evaluate their security requirements and consider re-encrypting
sensitive data using version 0.18.1 or 0.17.1.
